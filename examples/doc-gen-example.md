```markdown
# 渗透测试技术评审规则

## 1. 评审范围

> 来源: [knowledge/real-world/pen-test-lessons.md](../knowledge/real-world/pen-test-lessons.md)

评审覆盖以下维度：
- 漏洞描述的准确性（是否超出证据范围）
- 优先级排序的合理性（CVSS + 业务影响）
- 交付物的分层完整性（执行摘要/详细报告/修复指南）

## 2. 核心评审规则

### 规则 1：证据先行
> 来源: [pen-test-lessons.md#踩坑3](../knowledge/real-world/pen-test-lessons.md)

所有漏洞描述必须附带复现步骤和截图证据，禁止超出证据范围的推断。

**反模式案例**: 将"可绕过认证"描述为"可获取全部用户数据"

### 规则 2：量化评分 + 业务影响
> 来源: [pen-test-lessons.md#踩坑1](../knowledge/real-world/pen-test-lessons.md), [pen-test-lessons.md#踩坑2](../knowledge/real-world/pen-test-lessons.md)

修复优先级 = CVSS 评分 × 业务影响系数

| 技术风险 | 业务影响 | 最终优先级 |
|----------|----------|------------|
| CVSS ≥ 9.0 | 影响核心业务 | P0 — 立即修复 |
| CVSS ≥ 7.0 | 影响用户隐私 | P1 — 一周内修复 |
| CVSS ≥ 4.0 | 无直接业务影响 | P2 — 计划内修复 |

### 规则 3：分层交付
> 来源: [pen-test-lessons.md#最佳实践](../knowledge/real-world/pen-test-lessons.md)

| 角色 | 交付物 | 关注点 |
|------|--------|--------|
| 管理层 | 执行摘要 | 风险总量、业务影响、修复成本估算 |
| 技术负责人 | 详细报告 | 漏洞详情、攻击路径、影响面 |
| 开发团队 | 修复指南 | 具体修复步骤、代码示例、复测方法 |

## 3. 踩坑经验

<!-- TODO-VERIFY: 以下经验是否覆盖全部关键场景 -->

- **坑 1**: 原始笔记缺乏 CVSS 评分 → **教训**: 测试笔记模板中增加 CVSS 评分字段作为必填项
- **坑 2**: 纯技术排序脱离客户实际 → **教训**: 启动阶段收集业务上下文信息
- **坑 3**: AI 描述超出证据范围 → **教训**: Reviewer Simulator 三视角审查不可省略

## 4. 待验证项

<!-- TODO-VERIFY: 以下待验证项需安全专家确认 -->

| 待验证项 | 验证方法 | 责任人 | 状态 |
|---------|---------|--------|------|
| CVSS 评分标准是否适用本场景 | 对照 NIST SP 800-115 | 安全专家 A | ⏳ |
| 业务影响映射规则是否合理 | 参考历史交付报告 | 项目经理 B | ⏳ |
| 分层交付模板是否完整 | 对比 3 个历史交付包 | 交付团队 C | ⏳ |

## 5. 可落地实践

1. 使用标准化测试笔记模板（含 CVSS 评分字段）
2. 每个漏洞必须附带复现截图和步骤
3. Reviewer Simulator 三视角审查（客户/开发/合规）
4. 修复优先级 = CVSS × 业务影响
5. 按角色分层交付（执行摘要/详细报告/修复指南）
```

| # | 待验证项 | 验证方法 | 责任人 | 状态 |

| 1 | CVSS 评分标准是否适用 | 对照 NIST SP 800-115 确认评分维度与本场景匹配 | 安全专家 A | ⏳ |
| 2 | 业务影响映射规则 | 参考历史交付报告，验证优先级矩阵覆盖典型场景 | 项目经理 B | ⏳ |
| 3 | 分层交付模板完整性 | 对比 3 个历史交付包，确认各角色关注点无遗漏 | 交付团队 C | ⏳ |

## 步骤 4: 人工校对

### 校对记录

| 待验证项 | 专家意见 | 修正内容 | 校对结果 |
|---------|---------|---------|---------|
| #1 CVSS 评分标准 | "CVSS v3.1 适用，但需补充攻击复杂度维度" | 在规则 2 中增加 `attack_complexity` 字段 | ✅ 已修正 |
| #2 业务影响映射 | "历史报告中有 2 个案例不支持当前矩阵，需调整 P1/P2 阈值" | 调整 P1 阈值为 CVSS ≥ 7.0 且影响用户隐私 | ✅ 已修正 |
| #3 分层交付模板 | "缺少给合规团队的交付物" | 增加合规视角：审计报告 + 风险披露说明 | ✅ 已修正 |
| #4 证据先行规则 | "充分，历史无证据不足通过评审的案例" | 无需修改 | ✅ 已确认 |
| #5 AI 编造防范 | "需增加具体检查项：描述中是否包含未在复现步骤中出现的技术细节" | 在 Reviewer Simulator 检查清单中增加 hallucination 检测项 | ✅ 已修正 |

### 校对结论

- 全部 5 个待验证项已完成校对
- 3 项需修正（#1, #2, #3），1 项确认无需修改（#4），1 项需补充检查项（#5）
- 所有修正已合并到最终版本
