# BOS-FS 产品交付辅助 Skill 使用指南

> **定位**: BOS-FS 是**产品交付辅助 Skill**，可集成到任意 AI Agent（Cursor / Trae / OpenHands / Claude Code），帮助**任何交付团队**把项目的"能力"转化为"可被理解、评估、接受的交付物"。
>
> 用途: 提供 8 大通用交付场景的标准化流水线，覆盖软件产品、技术文档、开源项目、安全服务、咨询报告、项目评审、数据处理脚本、团队知识沉淀。
>
> 受众: 产品团队负责人、项目经理、技术负责人、安全工程师、技术文档工程师、咨询顾问、任何需要交付标准化文档的角色。

## BOS-FS 交付流水线

所有 8 个场景共享同一套核心流水线，各场景的差异仅体现在输入数据和输出模板上。

```
原始数据 → Goal Refiner → Outcome Mapper → Reviewer Simulator → README Refactor → Submission Builder → 完整交付包
```

| 阶段 | 技能 | 作用 | 适用场景 |
|------|------|------|---------|
| Understand | **Goal Refiner** | 将零散数据转化为结构化信息 | 所有场景 |
| Map | **Outcome Mapper** | 按目标受众映射价值/优先级 | 所有场景 |
| Review | **Reviewer Simulator** | 模拟多视角评审，提前发现问题 | 所有场景 |
| Refactor | **README Refactor** | 将结构化数据转换为标准文档 | 所有场景 |
| Build | **Submission Builder** | 生成完整交付包（多组件） | 所有场景 |

> **配置灵活性**: 支持自定义评审规则、输出组件、场景模板。详见 [engine/README.md](../engine/README.md)

## 场景 1: 软件产品交付

### 背景

产品团队完成开发后，需要将技术能力转化为面向客户/管理层的交付文档。技术团队擅长实现，但往往不擅长将技术能力转化为商业价值表达。

### BOS-FS 如何帮助

| 阶段 | 传统方式 | BOS-FS 方式 |
|------|---------|------------|
| 需求理解 | 口头交接或零散文档 | Goal Refiner 提炼 persona/problem/solution/outcome |
| 价值表达 | 技术语言描述功能 | Outcome Mapper 转换为 Feature→Capability→Outcome |
| 文档生成 | 手动编写 README/说明书 | README Refactor 自动生成标准化文档 |
| 质量预审 | 交付后才发现问题 | Reviewer Simulator 模拟四类评审（用户/安全/运维/决策者），提前发现问题 |
| 交付构建 | 零散文件打包 | Submission Builder 生成完整交付包 |

### 输入输出

**输入**: 项目描述、功能列表、目标用户信息、技术架构描述

**输出**:
- 产品价值说明 (面向管理层/客户)
- 技术文档 (面向开发/运维团队)
- 用户指南 (面向终端用户)
- 完整交付文档包 (README/CONTRIBUTING/SECURITY/CHANGELOG)

### 效率指标

| 指标 | 传统方式 | BOS-FS |
|------|---------|--------|
| 文档准备时间 | 3-5 天 | 1-2 天 |
| 技术→商业语言转换 | 手动，易遗漏关键价值点 | 自动映射，确保完整性 |
| 评审通过率 | ~50% | ~85% |

### 真实案例

[**case-04: AI Workflow Engine 产品交付**](../examples/real-cases/case-04-product-delivery.md) — 将零散技术笔记转化为 7 组件完整交付包，文档撰写时间缩减 67%，接入效率从 1 天缩短至 5 分钟。

技术文档（API 文档、架构设计文档、部署指南等）需要满足特定质量标准，但编写者往往难以自查文档是否完整、准确、易于理解。

### BOS-FS 如何帮助

| 阶段 | 传统方式 | BOS-FS 方式 |
|------|---------|------------|
| 文档规划 | 凭经验确定章节 | 基于知识体系的标准化模板 |
| 内容编写 | 手动编写，格式不统一 | 结构化引导，自动格式化 |
| 质量检查 | 人工评审，易遗漏 | 自动审查完整性/准确性/可读性 |
| 评审模拟 | 交付后才收到反馈 | 模拟技术评审/架构评审视角 |

### 输入输出

**输入**: 项目代码、架构描述、API 定义、部署配置

**输出**:
- 架构设计文档
- API 参考文档
- 部署与运维指南
- 完整技术文档包

### 效率指标

| 指标 | 传统方式 | BOS-FS |
|------|---------|--------|
| 文档编写时间 | 3-5 天 | 1-2 天 |
| 质量审查轮次 | 2-3 轮 | 0-1 轮 |
| 文档一致性 | 依赖个人水平 | 标准化模板保证 |

## 场景 3: 开源项目交付

### 背景

开源项目需要完整的交付物（README、贡献指南、行为准则、许可证、安全策略等），但很多项目缺乏这些标准化文件，导致社区参与度低。

### BOS-FS 如何帮助

| 阶段 | 传统方式 | BOS-FS 方式 |
|------|---------|------------|
| 许可证选择 | 随意选择或忽略 | 基于项目特点推荐 |
| 贡献指南 | 简单几句话 | 标准化贡献流程文档 |
| 安全策略 | 往往缺失 | 自动对齐 OWASP 基准 |
| 信任声明 | 无 | 对标 CII Best Practices 自动生成 |

### 输入输出

**输入**: 项目描述、技术栈、依赖列表

**输出**:
- README (项目介绍/安装/使用/贡献)
- CONTRIBUTING.md (贡献指南)
- CODE_OF_CONDUCT.md (行为准则)
- SECURITY.md (安全策略)
- LICENSE (许可证建议)
- 信任声明 (对标行业标准)

### 效率指标

| 指标 | 传统方式 | BOS-FS |
|------|---------|--------|
| 交付物完整性 | ~40% 项目缺失关键文件 | 100% 覆盖标准交付物 |
| 准备时间 | 1-2 周 | 半天 |
| 社区信任度 | 低 (缺乏标准文件) | 高 (对齐行业标准) |

### 真实案例

[**case-05: my-data-cleaner 开源项目交付**](../examples/real-cases/case-05-opensource-delivery.md) — 将仅有 3 行 README 的半成品项目转化为 12 组件标准开源项目，总耗时从 1-2 周缩减至半天，交付物完整性从 30% 提升至 100%。

### BOS-FS 如何帮助

| 阶段 | 传统方式 | BOS-FS 方式 |
|------|---------|------------|

| 维护更新 | 脚本更新后文档过时 | 文档随脚本同步更新 |

### 输入输出

**输入**: 原始脚本、数据样例、处理逻辑描述

**输出**:
- README (项目说明、安装、使用)
- 使用指南 (详细步骤、参数说明)
- FAQ (常见问题解答)
- 示例数据与输出

### 价值

| 维度 | 说明 |

| 知识沉淀 | 新人可直接使用，无需口头传授 |

## 决策指南

### 何时应该使用 BOS-FS

| 信号 | 说明 |
|------|------|
| 文档准备占项目时间 >20% | BOS-FS 可显著缩短文档周期 |
| 交付物质量参差不齐 | BOS-FS 提供标准化输出 |
| 评审通过率低 | BOS-FS 模拟评审，提前发现问题 |
| 新人上手慢，知识难传承 | BOS-FS 沉淀交付模板与流程 |
| 客户/评审对交付物反复提出修改 | BOS-FS 确保首次交付质量 |
| 多项目并行，交付压力大 | BOS-FS 提升并发处理能力 |

### 何时不适合

| 情况 | 说明 |
|------|------|
| 纯技术探索，无交付需求 | BOS-FS 关注交付而非生成 |
| 已有成熟自动化报告系统 | 需评估替代收益 |
| 项目周期极短 (<1天) | 引入成本可能超过收益 |

## 配置灵活性

BOS-FS 提供完整的配置系统，支持不同团队按自身标准定制：

- **自定义评审规则** — 调整维度权重、评分阈值、缺陷惩罚规则
- **自定义输出组件** — 增删交付物组件，选择输出格式（Markdown/JSON/HTML）
- **场景配置模板** — 预定义各场景配置（软件产品/技术文档/开源项目/安全服务/咨询报告/项目评审/脚本交付/知识沉淀）
- **配置加载优先级** — 硬编码默认值 < JSON 默认配置 < 用户自定义配置 < 场景配置

详细配置指南 → [engine/README.md](../engine/README.md)
